# Student Digital Addiction Analysis

A B.Tech mini-project that analyzes student digital habits with Python, Pandas, visualization, a baseline Random Forest classifier, and a Streamlit dashboard.

## Features
- Dataset overview and KPI cards
- Screen-time, sleep, study, gaming, social media, and notification exploration
- Risk category distribution and correlation visualization
- CSV upload and download
- Baseline ML model with test accuracy, classification report, and confusion matrix
- Interactive hypothetical-student tool
- Privacy and limitations notes

## Important data note
`data/student_digital_habits_synthetic.csv` is a **synthetic demonstration dataset** generated for this project. It does not represent real students. Its risk labels are generated by an illustrative rule using usage and routine features. Consequently, ML results are only a demonstration of the workflow and must not be presented as validated detection of clinical addiction. Replace it with properly collected, consented and anonymized data, and define the target label using a defensible survey instrument before making research claims.

## Setup (Windows / VS Code)
Use Python 3.11 or 3.12 for compatibility.

```powershell
cd path\to\Student_Digital_Addiction_Analysis
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
streamlit run app.py
```

If PowerShell blocks activation, run this in the current terminal:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```
Alternative without activation:
```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Open the local URL Streamlit prints, usually `http://localhost:8501`.

## CSV schema for uploads
Required columns:
- `daily_screen_time_hours`
- `social_media_hours`
- `gaming_hours`
- `sleep_hours`
- `study_hours`
- `notifications_per_day`
- `academic_performance_score`
- `risk_level` (Low, Moderate, High)

Optional columns: `student_id`, `age`, `gender`.

Keep personal identifiers out of uploaded datasets. The app expects a pre-defined `risk_level` target for ML training.

## Testing checklist
1. Run the app and confirm the Overview tab loads.
2. Confirm the sample records and CSV download work.
3. Change the metric in Explore Data and confirm the histogram updates.
4. Filter risk categories and verify displayed row count changes.
5. Select different x/y axes in Relationships.
6. Train the baseline model and inspect metrics and confusion matrix.
7. Adjust the hypothetical student sliders and click Estimate category.
8. Upload a CSV with required columns and verify it loads.
9. Upload a CSV missing `risk_level` and confirm a clear validation message appears.
